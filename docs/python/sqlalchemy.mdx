## 安装

适用 Python 3.10+、SQLAlchemy 2.x 和 PostgreSQL。这里使用 `asyncpg`；[FastAPI 登录示例](/blog/fastapi) 选择的是 MySQL/`aiomysql`，会话模式类似，但连接串与数据库特有类型需要分别配置。

```bash
# asyncpg 是异步 PostgreSQL 驱动，与下面 postgresql+asyncpg 的连接串对应
uv add "sqlalchemy[asyncio]>=2,<3" asyncpg

# 同步程序可另选 psycopg 驱动；Alembic 也支持异步模板，并非必须使用同步驱动
# uv add psycopg2-binary
```

## PostgreSQL 连接

连接部分分为四块：**引擎**、**会话工厂**、**声明式基类**、**依赖注入函数**。

先提供环境配置，在包目录创建 `__init__.py`。密码只从环境读取，不写入文章或仓库。

```python title="db/config.py" showLineNumbers
HOST = os.environ.get("PGHOST", "127.0.0.1")
PORT = int(os.environ.get("PGPORT", "5432")) # 环境变量是字符串，端口显式转成整数
USER = os.environ["PGUSER"]
PASSWORD = os.environ["PGPASSWORD"]
DB_NAME = os.environ["PGDATABASE"]
```

### 创建异步引擎

```python title="db/engine.py" showLineNumbers
# URL.create 会自动处理密码中的特殊字符（@ : / 等），比手写 f-string 拼接更安全
PG_DATABASE_URL = URL.create(
    "postgresql+asyncpg",
    username=USER,
    password=PASSWORD,
    host=HOST,
    port=PORT,
    database=DB_NAME,  # 库名使用单独的配置，不要和用户名混用
)

# create_async_engine 创建异步引擎实例
engine = create_async_engine(PG_DATABASE_URL, pool_pre_ping=True)
```

### 会话工厂与声明式基类

```python title="db/session.py" showLineNumbers
# async_sessionmaker 异步会话工厂，用于创建数据库会话
# AsyncSession 异步数据库会话类
SessionLocal = async_sessionmaker(
    bind=engine,            # 绑定到之前创建的异步引擎
    class_=AsyncSession,    # 指定使用异步会话类
    expire_on_commit=False, # 提交后保留已加载的属性，不自动重新查询
)

# DeclarativeBase ORM 声明式基类，所有数据模型都继承自它
class Base(DeclarativeBase):
    pass
```

`expire_on_commit` 的行为差异：

| 取值 | 事务提交后 | 适用场景 |
| --- | --- | --- |
| `True`（默认） | 对象属性过期，下次访问通常需重新查库 | 同步代码中按需刷新属性；异步访问需显式处理 |
| `False`（异步常用） | 已加载属性保持可用，可能已不是数据库最新值 | Web 接口返回对象、避免隐式 IO |

<Callout type="note" title="异步下不要依赖隐式懒加载">
`AsyncSession` 中访问尚未加载的属性或关系，会因为触发隐式 IO 而抛出 `MissingGreenlet`。`expire_on_commit=False` 解决的是提交后属性过期的问题；关系字段需要在定义时用 `lazy="selectin"`，或在查询时用 `selectinload` / `joinedload` 主动加载。
</Callout>

属性不过期不代表严格一致；需要最新数据时显式 `await session.refresh(obj)`，并结合事务隔离级别决定可见性。每个请求或并发任务使用自己的 `AsyncSession`。

### 依赖注入函数

```python title="db/deps.py" showLineNumbers
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with SessionLocal() as session:
        yield session # 每个请求独享会话，依赖退出时关闭连接
```

## 定义实体类

关系两端分别定义 `User` 和 `GirlfriendConfig`，启动时注册两个模型。

```python title="models/user.py" showLineNumbers
class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    code: Mapped[str] = mapped_column(String(64), unique=True)
    user_name: Mapped[str] = mapped_column(String(100))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(),
    )
    girlfriend_configs: Mapped[list["GirlfriendConfig"]] = relationship(
        back_populates="user", cascade="save-update, merge, delete, delete-orphan", passive_deletes=True,
        lazy="selectin", # 批量预加载关系，避免访问字段时触发异步隐式 IO
    )
```

### 实体类定义

```python title="models/girlfriend_config.py" showLineNumbers
class GirlfriendConfig(Base):
    """
    女友配置实体类
    对应数据库表：girlfriend_configs
    """

    # 1. 表名定义
    __tablename__ = "girlfriend_configs"

    # 2. 表级参数（可选）
    __table_args__ = {
        "comment": "用户女友配置表",   # 表注释
    }

    # ========== 字段定义 ==========

    # 3. 主键字段
    id: Mapped[int] = mapped_column(
        Integer,
        primary_key=True,
        autoincrement=True,
        comment="配置ID",
    )

    # 4. 外键字段（关联用户表）
    user_id: Mapped[int] = mapped_column(
        BigInteger,                                  # 类型要和 users.id 保持一致
        ForeignKey("users.id", ondelete="CASCADE"),  # 删除时级联
        nullable=False,
        index=True,                                  # 创建索引，提升查询速度
        comment="关联的用户ID",
    )

    # 5. 字符串字段
    nickname: Mapped[str] = mapped_column(
        String(50),
        nullable=False,
        default="默认昵称",  # Python 层默认值（应用层）
        comment="女友昵称",
    )

    # 6. 长文本字段
    personality: Mapped[Optional[str]] = mapped_column(
        TEXT,
        nullable=True,
        comment="性格描述，支持长文本",
    )

    # 7. 时间字段 - 创建时间
    created_at: Mapped[datetime] = mapped_column(
        TIMESTAMP(timezone=True),
        server_default=func.now(),  # 数据库默认值，插入时自动设置
        nullable=False,
        comment="创建时间",
    )

    # 8. 时间字段 - 更新时间
    updated_at: Mapped[datetime] = mapped_column(
        TIMESTAMP(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),  # SQLAlchemy 生成 UPDATE 时加入；不是数据库触发器
        nullable=False,
        comment="最后更新时间",
    )

    # 9. 布尔字段
    is_active: Mapped[bool] = mapped_column(
        Boolean,
        default=True,
        nullable=False,
        comment="是否激活（True=激活，False=禁用）",
    )

    # ========== 关系定义 ==========

    # 10. 定义关联关系
    user: Mapped["User"] = relationship(
        back_populates="girlfriend_configs",  # User 类中对应的属性名
        lazy="selectin",                      # 异步下用 selectin，不要用默认的 select 懒加载
    )

    # ========== 特殊方法 ==========

    def __repr__(self):
        """对象字符串表示，用于调试"""
        return f"<GirlfriendConfig(id={self.id}, nickname='{self.nickname}')>"

    def to_dict(self):
        """转换为字典，用于 API 响应"""
        return {
            "id": self.id,
            "nickname": self.nickname,
            "personality": self.personality,
            "created_at": self.created_at.isoformat() if self.created_at else None,
            "is_active": self.is_active,
        }
```

### 常用数据类型速查

| Python 类型 | SQLAlchemy 类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `str` | `String(255)` | VARCHAR(255) | 短字符串 |
| `str` | `Text()` | TEXT | 长文本 |
| `int` | `Integer()` | INT | 整数 |
| `int` | `BigInteger()` | BIGINT | 大整数 |
| `bool` | `Boolean()` | BOOLEAN | 布尔值 |
| `datetime` | `DateTime()` | TIMESTAMP WITHOUT TIME ZONE（PostgreSQL） | 日期时间，其他方言可能用 DATETIME |
| `datetime` | `TIMESTAMP()` | TIMESTAMP | 时间戳 |
| `float` | `Float()` | FLOAT | 浮点数 |
| `Decimal` | `Numeric(10,2)` | DECIMAL(10,2) | 精确小数 |
| `bytes` | `LargeBinary()` | BLOB（PostgreSQL 中为 BYTEA） | 二进制数据 |

### 扩展类型

| Python 类型 | SQLAlchemy 类型 | 数据库类型 | 示例 |
| --- | --- | --- | --- |
| `date` | `Date()` | DATE | `2023-12-25` |
| `time` | `Time()` | TIME | `14:30:00` |
| `timedelta` | `Interval()` | INTERVAL | 时间间隔 |
| `list` | `ARRAY(String)` | ARRAY（PostgreSQL 等少数数据库支持） | 字符串数组 |

| `uuid.UUID` | `UUID()` | UUID | UUID 类型 |
| `enum.Enum` | `Enum()` | ENUM | 枚举类型 |

| `str` | `VARCHAR(100)` | VARCHAR(100) | 变长字符串（与 `String(100)` 等价） |
| `int` | `SmallInteger()` | SMALLINT | 小整数 |

### 常见配置选项

| `mapped_column()` 参数 | 适用类型 | 示例 | 效果 |
| --- | --- | --- | --- |
| `primary_key=True` | 所有类型 | `mapped_column(primary_key=True)` | 设置为主键 |
| `autoincrement=True` | Integer/BigInteger | `mapped_column(autoincrement=True)` | 自动递增 |
| `nullable=False` | 所有类型 | `mapped_column(nullable=False)` | 不允许 NULL |
| `unique=True` | String/Integer 等 | `mapped_column(unique=True)` | 值必须唯一 |
| `index=True` | 取决于数据库/索引方法支持 | `mapped_column(index=True)` | 创建普通索引，需与查询方式匹配 |
| `default=值` | 所有类型 | `mapped_column(default="默认")` | Python 默认值 |
| `server_default=值` | 所有类型 | `server_default=func.now()` | 数据库默认值 |
| `onupdate=值` | DateTime/TIMESTAMP | `onupdate=func.now()` | 更新时自动设置 |
| `ForeignKey()` | 所有类型 | `mapped_column(ForeignKey("users.id"))` | 设置为外键 |

## 编写接口的流程

写接口时按下面六步推进：

| 步骤 | 内容 |
| --- | --- |
| 1 | 定义传参和数据库会话 |
| 2 | 处理边界条件 |
| 3 | 处理逻辑（可计算部分） |
| 4 | 定义 SQL |
| 5 | 执行 SQL，写入时按业务边界提交事务 |
| 6 | 根据 SQL 返回内容定义接口返回值 |

```python title="api/user.py" showLineNumbers
router = APIRouter()

@router.get("/info", response_model=Result[dict], summary="获取用户信息", tags=["角色信息"])
async def get_user_info(
    db: AsyncSession = Depends(get_db),      # step 1. 数据库会话
    code: Optional[str] = Header(None),      # step 1. 传参
):
    # step 2. 边界条件
    if code is None:
        raise ParameterException("用户不存在", code=404)

    # step 3. 处理逻辑（本例没有需要计算的部分）

    # step 4. 定义 SQL（变量名用 stmt，不要和实体变量混淆）
    stmt = select(User.created_at, User.id, User.user_name).where(User.code == code)

    # step 5. 执行查询，不需要 commit
    result = await db.execute(stmt)

    # step 6. 根据 SQL 返回内容定义接口返回值
    row = result.one_or_none()
    if row is None:
        raise ParameterException("用户不存在", code=404)

    created_at, user_id, user_name = row
    # 每次请求都新建响应对象；不要把响应对象定义成全局变量再修改，并发请求会互相覆盖
    return Result.ok(data={
        "createTime": created_at,
        "userId": user_id,
        "userName": user_name,
    })
```

该接口是接入 FastAPI 工程的片段，`app.core` 模块来自 [FastAPI 示例](/blog/fastapi#集中异常处理)；把本篇的 `db`、`models` 包放在项目根目录，并由入口注册 `router`。它不是独立运行的脚本。

初始化数据库时需 `import models.user` 和 `import models.girlfriend_config` 注册元数据，再在 `async with engine.begin() as conn` 中执行 `await conn.run_sync(Base.metadata.create_all)`。这只创建缺失的表，不替代结构迁移；生产环境使用 Alembic。程序结束时执行 `await engine.dispose()` 释放连接池。

常用的会话操作（注意哪些需要 `await`）：

```python title="session_methods.py" showLineNumbers
await db.execute(stmt)       # 执行 SQL 并拿到结果，不等于提交事务
await db.commit()            # 提交本次事务，持久化写入
db.add(obj)                  # 新增一个对象（同步方法，不需要 await）
db.add_all([obj1, obj2])     # 批量新增（同步方法）
await db.delete(obj)         # 删除对象（异步方法，需要 await）
```

以上是异步函数内部的方法速查，`db`、`stmt` 和对象由调用方提供。写操作也可以用 `async with SessionLocal.begin() as db:`，退出时成功提交、异常回滚；不要在这个上下文内部另行提前 `commit()`。查询同样会开启事务，会话关闭时会结束尚未提交的事务。

### Result 常用方法

`result` 是数据库执行 SQL 后返回的结果容器。更新/删除的 `rowcount` 是否可靠取决于驱动与语句，可能为 `-1`；不要将它用于普通 SELECT 的结果计数。

| 方法 | 返回 | 说明 | 适用查询 |
| --- | --- | --- | --- |
| `result.one_or_none()` | 单行或 `None` | 不存在返回 `None`，多行报错 | 多列，如 `select(User.psd, User.code)` |
| `result.scalar_one_or_none()` | 单值或 `None` | 不存在返回 `None`，多行报错，自动解包 | 单列或单个实体，如 `select(User).where(User.id == userid)` |
| `result.one()` | 单行 | 不存在或多行都报错 | 业务要求恰好一行的多列查询 |
| `result.first()` | 第一行或 `None` | 不存在返回 `None` | 多列 |
| `result.all()` | 列表 | 取所有行 | 多列 |
| `result.scalar()` | 单值或 `None` | 取第一行第一列，不验证唯一性 | 单列 |
| `result.scalars().all()` | 扁平列表 | 只查一列时返回 `[1, 2, 3]` | 单列 |
| `result.mappings().all()` | RowMapping 列表 | 按列名访问；`[dict(row) for row in ...]` 转成普通字典 | 多列 |

## 构建 SQL 语句

下面是聚合查询的结构模板，假设另有包含 `user_id` 的 `Order` 模型，且 `User` 有 `city`、`age`、`is_active` 列；这些字段不属于上面的最小模型。实际调用放在异步函数中，按自己的实体替换。

```python title="query.py" showLineNumbers
# User、Order 为已定义的实体类；下面统计「订单数超过 5 的城市」
stmt = (
    select(User.city, func.count(Order.id).label("order_count"))  # 1. 选择列（分组查询只能选分组列和聚合列）
    .join(Order, User.id == Order.user_id)        # 2. JOIN
    .where(User.is_active.is_(True))              # 3. WHERE 条件
    .where(User.age >= 18)                        # 4. 可以多个 where
    .group_by(User.city)                          # 5. GROUP BY
    .having(func.count(Order.id) > 5)             # 6. HAVING 条件
    .order_by(func.count(Order.id).desc())        # 7. ORDER BY（分组后只能按分组列或聚合结果排序）
    .limit(10)                                    # 8. LIMIT
    .offset(20)                                   # 9. OFFSET
)

rows = (await db.execute(stmt)).all()             # 10. 执行，返回 [(city, order_count), ...]
```

<Callout type="tip" title="DISTINCT 与分组查询">
`GROUP BY` 决定分组粒度，`DISTINCT` 对最终选择列去重，二者不等价。例如按城市分组却只选订单数量时，不同城市可能得到同一个数量。通常选择了分组键的聚合查询不再需要额外去重。在 PostgreSQL 中，`select(User)` 配合 `group_by(User.city)` 会因其他列没有分组或聚合而报错；主键带来的函数依赖是另一种情况。
</Callout>
