Git 的核心工作区分为工作目录、暂存区和本地仓库。操作前先看状态，提交前再看差异。

## 状态与提交

```bash
git status
git diff
git add src/app/page.tsx
git commit -m "feat: update home page"
git push
```

状态中的 `M` 表示修改，`A` 表示新增，`D` 表示删除，`R` 表示重命名，未跟踪文件通常以 `??` 显示。

## 分支协作

```bash
git switch -c feature/filter-posts
git push -u origin feature/filter-posts
git switch main
git merge feature/filter-posts
```

分支名应表达任务意图。合并前同步目标分支，并运行项目的检查命令。

## 储藏与恢复

```bash
git stash push -u -m "wip: filter ui"
git stash list
git stash pop
```

储藏适合短暂切换上下文，不应替代正常提交。

## 冲突与回滚

冲突文件会包含当前分支与待合并分支的标记。人工确定最终内容，删除标记并重新暂存。

已经推送到共享分支的提交优先使用 `git revert <commit>` 生成反向提交，保留完整历史；不要随意改写其他人依赖的远程历史。
