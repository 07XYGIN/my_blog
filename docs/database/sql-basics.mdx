以下示例以 MySQL 8.0.16+ 与 PostgreSQL 13+ 共有的语法为主。数据库管理、类型与特有函数见 [MySQL 与 PostgreSQL：常用语法差异](/blog/mysql-postgresql)。各小节用于独立查阅，涉及同名表时应使用自己的练习数据库。

## 1. SQL 语句分类

| 类型 | 说明 | 常见语句 |
| ---- | ---- | -------- |
| DDL | 定义、修改、删除数据库对象结构 | `CREATE`、`ALTER`、`DROP` |
| DML | 插入、更新、删除表中的数据 | `INSERT`、`UPDATE`、`DELETE` |
| DQL | 查询数据 | `SELECT` |
| DCL | 管理访问权限 | `GRANT`、`REVOKE` |
| TCL | 管理事务 | `BEGIN`、`COMMIT`、`ROLLBACK` |

---

## 2. DDL：表结构操作

```sql
-- 创建表
CREATE TABLE IF NOT EXISTS users (
    id BIGINT PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 新增字段
ALTER TABLE users ADD COLUMN status VARCHAR(20) DEFAULT 'active';

-- 删除字段
ALTER TABLE users DROP COLUMN status;

```

需要清理练习表时再执行 `DROP TABLE IF EXISTS users;`。`DROP TABLE` 删除表结构和数据，不要在后续查询仍需使用该表时执行。

自增主键、表注释、字符集、分区等语法在不同数据库中差异较大，见[差异参考](/blog/mysql-postgresql#建表-主键与注释)。

## 3. DML：增删改

```sql
-- 插入一条数据
INSERT INTO users (id, username, email)
VALUES (1, 'alice', 'alice@example.com');

-- 插入多条数据
INSERT INTO users (id, username, email)
VALUES
    (2, 'bob', 'bob@example.com'),
    (3, 'charlie', 'charlie@example.com');

-- 更新数据：一定要确认 WHERE 条件，避免全表更新
UPDATE users
SET email = 'new_email@example.com'
WHERE username = 'alice';

-- 删除数据：一定要确认 WHERE 条件，避免全表删除
DELETE FROM users
WHERE username = 'charlie';
```

## 4. DQL：查询

```sql
-- 查询所有列
SELECT * FROM users;

-- 指定列和条件
SELECT id, username, email
FROM users
WHERE username LIKE 'a%';

-- 常见条件组合
SELECT *
FROM users
WHERE (id > 10 AND email IS NOT NULL)
   OR username LIKE '%test%';

-- 聚合查询
SELECT COUNT(*) AS total_count,
       MAX(id) AS max_id,
       MIN(id) AS min_id
FROM users;

-- 分组和分组后过滤
SELECT username, COUNT(*) AS total_count
FROM users
WHERE created_at >= '2024-01-01'
GROUP BY username
HAVING COUNT(*) > 1;

-- 排序
SELECT *
FROM users
ORDER BY created_at DESC, id ASC;

-- 分页：MySQL 和 PostgreSQL 都支持 LIMIT (页大小) + OFFSET (偏移量)
-- 页大小：返回的条数
-- 偏移量：从第几条数据返回
SELECT *
FROM users
ORDER BY id
LIMIT 10 OFFSET 20;
-- 每页十条数据，返回第3页数据
-- 条数计算公式：偏移量 = (页码 - 1) * 页大小
```

页码从 1 开始时，偏移量为 `(page - 1) * pageSize`。分页必须配合稳定排序；排序列可能重复时追加主键，避免翻页结果漂移。大偏移量会增加扫描成本，可以考虑按上一页末尾的排序键继续查询。

条件中 `AND` 的优先级高于 `OR`，用括号写清分组。`NULL` 表示未知值，用 `IS NULL` / `IS NOT NULL` 判断，不能用 `= NULL`。

`LIKE` 常用通配符：

| 写法 | 含义 |
| ---- | ---- |
| `'a%'` | 以 `a` 开头 |
| `'%a'` | 以 `a` 结尾 |
| `'%a%'` | 包含 `a` |
| `'_a%'` | 第二个字符是 `a` |

## 5. 约束

约束用于限制表中的数据，保证数据的正确性、有效性和完整性。

| 约束 | 概述 | 关键字 |
| ---- | ---- | ------ |
| 非空约束 | 字段不能为 `NULL` | `NOT NULL` |
| 唯一约束 | 字段值不能重复 | `UNIQUE` |
| 主键约束 | 唯一且不能为空，标识每一行数据 | `PRIMARY KEY` |
| 默认约束 | 未指定字段值时使用默认值 | `DEFAULT` |
| 检查约束 | 字段值必须满足表达式条件 | `CHECK` |
| 外键约束 | 建立两张表之间的引用关系 | `FOREIGN KEY` |

```sql
CREATE TABLE departments (
    id BIGINT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE employees (
    id BIGINT PRIMARY KEY,
    department_id BIGINT NOT NULL,
    name VARCHAR(50) NOT NULL,
    salary DECIMAL(10, 2) NOT NULL CHECK (salary >= 0),
    CONSTRAINT fk_employees_department
        FOREIGN KEY (department_id) REFERENCES departments(id)
);
```

删除外键或约束的语法在 MySQL 和 PostgreSQL 中不完全一致，见[约束变更](/blog/mysql-postgresql#外键与约束变更)。`CHECK` 对结果为未知值的表达式通常不会判定违规，因此禁止空值仍需单独声明 `NOT NULL`。`UNIQUE` 也不能代替 `NOT NULL`。

## 6. 多表查询

推荐使用显式 `JOIN`，可读性更好，也更容易维护。

```sql
-- 内连接：只返回两张表都匹配的数据
SELECT e.id, e.name, d.name AS department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;

-- 左连接：保留左表全部数据，右表没有匹配则为 NULL
SELECT e.id, e.name, d.name AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id;

-- 右连接：保留右表全部数据，左表没有匹配则为 NULL
SELECT e.id, e.name, d.name AS department_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.id;
```

隐式连接也能使用，但容易产生笛卡尔积：

```sql
SELECT *
FROM departments d, employees e
WHERE d.id = e.department_id;
```

## 7. 索引

索引用于提升查询性能，常见场景包括 `WHERE`、`JOIN`、`ORDER BY`、`GROUP BY` 中频繁使用的字段。

```sql
-- 多列索引
CREATE INDEX idx_users_name_created_at ON users(username, created_at);
```

本例的 `email` 已有唯一约束，通常不再建立同列普通索引。多列索引的顺序由查询的等值过滤、范围过滤和排序方式共同决定，不能只按“区分度最高的列放第一位”机械选择。使用 `EXPLAIN` 核对实际计划；索引也会增加存储和写入维护成本。

示例：索引 `(username, created_at)` 可以优化：

```sql
WHERE username = 'alice'

WHERE username = 'alice'
  AND created_at >= '2024-01-01'
```

但通常不能很好优化只按第二列过滤的查询：

```sql
WHERE created_at >= '2024-01-01'
```

## 8. 事务

事务让一组数据修改可以作为整体提交或回滚。应用需要检查执行结果，并在失败时回滚；开启事务本身不会自动处理业务约束或所有数据库错误。

ACID：

| 特性 | 说明 |
| ---- | ---- |
| Atomicity 原子性 | 事务中的操作要么全部完成，要么全部不完成 |
| Consistency 一致性 | 事务应维持约束与业务不变量，依赖正确的约束和应用逻辑 |
| Isolation 隔离性 | 并发事务之间的数据可见性由隔离级别决定 |
| Durability 持久性 | 事务提交后，修改会被持久保存 |

```sql
CREATE TABLE accounts (
    id BIGINT PRIMARY KEY,
    balance DECIMAL(12, 2) NOT NULL CHECK (balance >= 0)
);
INSERT INTO accounts (id, balance) VALUES (1, 500.00), (2, 100.00);

BEGIN;
UPDATE accounts SET balance = balance - 100.00 WHERE id = 1;
UPDATE accounts SET balance = balance + 100.00 WHERE id = 2;
COMMIT;
```

这个示例假设两行存在且金额固定。真实转账还要检查受影响行数、余额、并发访问与重复请求。若执行失败，应在 `COMMIT` 前改为 `ROLLBACK`；提交以后再执行 `ROLLBACK` 不能撤销已经提交的修改。

MySQL 需使用支持事务的存储引擎（通常为 InnoDB），且许多 DDL 会隐式提交。PostgreSQL 中事务里的语句报错通常会使该事务进入失败状态，需要回滚，或者用预先建立的保存点恢复。不要假定不同数据库对每种错误的处理都相同。

## 9. 常见数据类型

具体范围、存储大小和别名在不同数据库中会有差异，下面记录通用理解。

### 9.1 数字类型

- `INTEGER` / `INT`：整数。
- `BIGINT`：大整数。
- `SMALLINT`：小范围整数。
- `DECIMAL(precision, scale)` / `NUMERIC(precision, scale)`：精确小数，适合金额等场景。
- `REAL` / `FLOAT` / `DOUBLE`：浮点数，适合近似计算。

### 9.2 字符串类型

- `CHAR(n)`：定长字符串。
- `VARCHAR(n)`：变长字符串。
- `TEXT`：长文本。

### 9.3 日期和时间类型

- `DATE`：日期，常见格式为 `YYYY-MM-DD`。
- `TIME`：时间，常见格式为 `HH:MM:SS`。
- `TIMESTAMP`：日期和时间。

## 10. 常见函数

```sql
SELECT
    CONCAT('hello', ' ', 'sql'),      -- 拼接字符串
    LOWER('ABC'),                    -- 转小写
    UPPER('abc'),                    -- 转大写
    LPAD('7', 3, '0'),               -- 左填充
    RPAD('7', 3, '0'),               -- 右填充
    SUBSTRING('abcdef', 2, 3),       -- 从第 2 位开始截取 3 个字符
    CEIL(1.2),                       -- 向上取整
    FLOOR(1.8),                      -- 向下取整
    MOD(10, 3),                      -- 取模
    ROUND(1.2345, 2),                -- 四舍五入并保留 2 位小数
    CURRENT_TIMESTAMP;               -- 当前时间 YYYY-MM-DD HH:mm:ss
```

随机数函数存在差异：MySQL 使用 `RAND()`，PostgreSQL 使用 `RANDOM()`。
