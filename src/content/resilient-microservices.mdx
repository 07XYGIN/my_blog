当设计分布式系统时，故障并不是异常，而是必须预期的状态。本文将探索如何结合 Go 的并发模型与 gRPC，构建不仅能从故障中存活，还能优雅处理故障的服务。

<h2 id="circuit-breaker">断路器模式</h2>

级联故障是微服务最难处理的问题之一。一个缓慢的依赖可能会占用整个基础设施中的资源。断路器模式会在下游服务出现问题时快速失败，从而阻止故障扩散。

```go
package main

import (
    "context"
    "log"
    "time"

    "github.com/sony/gobreaker"
)

func main() {
    // 初始化断路器
    cb := gobreaker.NewCircuitBreaker(gobreaker.Settings{
        Name:        "user-service",
        MaxRequests: 3,
        Interval:    5 * time.Second,
        Timeout:     10 * time.Second,
    })

    // 包装调用
    body, err := cb.Execute(func() (interface{}, error) {
        return fetchUserData(context.Background())
    })

    if err != nil {
        log.Printf("触发降级: %v", err)
    }
}
```

<h2 id="grpc-retries">配置 gRPC 重试</h2>

默认情况下，gRPC 客户端不会重试失败的调用。不过，你可以在客户端连接的拨号选项中直接配置精细的重试逻辑。

- **透明重试：** 如果请求在离开客户端前失败，gRPC 会自动处理重试。
- **可配置重试：** 可以为特定状态码（例如 `UNAVAILABLE`）定义策略。
- **指数退避：** 避免让正在承压的服务雪上加霜。

> 韧性的关键不是完全阻止故障，而是确保小故障不会演变为全局宕机。
