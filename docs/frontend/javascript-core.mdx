## 浏览器加载与 JavaScript 执行流程

输入网址后，浏览器会依次进行 DNS 解析、获取 IP 地址、加载 `index.html`，遇到 `script` 标签后下载 JavaScript。

JS 的代码是通过浏览器内核解析的

HTML 和 CSS 会分别由对应的解析引擎转换为 DOM 树和 CSSOM 树。解析 HTML 时如果遇到同步脚本，浏览器通常会暂停解析，待 JavaScript 引擎执行后再继续。

JavaScript 引擎（例如 V8）会将 JavaScript 代码转换为机器码。

JavaScript → V8 引擎解析 → AST

### get/set
`getter`: 不可以传参，在调用的时候会触发
`setter`: 可以传参，在传参的时候会触发
出现他俩时，不可以有同名方法或函数
```javascript
class b{
    constructor(a){
        this.a = a
    }
    set add(num){
        this.a = num
        console.log(this.a);
        console.log('set');
        console.log(num);

    }
    get add(){
        console.log('get');
    }
}

const bb = new b(1)

bb.add = 5  // 5 set 5
bb.add //get
```
Q：在使用set时 为什么bb.add = 5可以打印到参数5 bb.add(5)就会报错
A：在 JS 中，`setter` 和 `getter` 要使用赋值语法，而不是调用语法，因为它们不是普通的**函数**。

## Promise 与事件循环

## eventLoop

事件循环会先执行当前宏任务，再清空微任务队列，然后进入下一个宏任务，如此循环直到任务全部完成。

如果存在嵌套任务：

- 微任务中产生宏任务：先执行微任务，再将宏任务放入队列。
- 宏任务中产生微任务：先完成当前宏任务，然后立即清空它产生的微任务。

## 函数和 this 指向
`this` 的值不是由**定义位置**决定的，而是由**调用方式**决定的。

常见情况如下：

1. 直接调用函数（严格模式下是 `undefined`）。
```javascript
function fn(){
  console.log(this)
}
fn() //window
```
2. 函数作为对象的属性（此时称为方法），`this` 指向该对象。
```javascript
  const person = {
    name: "Alice",
    greet: function () {
        console.log(this);
    },
    setName:()=>{
      console.log(this); //箭头函数没有自己的this,它指向最外层作用域 输出window
    }
  };
person.greet(); //{name,greet}
```
2.1 如果把这个方法赋值给新的变量，调用时 `this` 通常指向 `window`。
```javascript
const myGreet = person.greet;
myGreet(); // window
```
3. 使用`new`来创建函数，那么this指向为这个函数
```javascript
function Person(name) {
  // this = {}; （JavaScript 引擎隐式创建）
  this.name = name;
  this.sayName = function() {
    console.log(this);
  };
  // return this; （JavaScript 引擎隐式返回）
}
const alice = new Person('Alice');
alice.sayName(); // 输出：Alice
// this 指向新创建的 alice 对象
```
4. 箭头函数没有自己的 `this`，它会继承定义所在作用域的 `this`。
5. 使用 `call`、`apply` 和 `bind` 修改 `this` 绑定。

```javascript
Function.prototype.call(thisArg, arg1, ...args)
Function.prototype.bind(thisArg, arg1, ...args) // 返回一个新函数
Function.prototype.apply(thisArg, [arg1, ...args])


```

## Vue

## Vue2 / Vue3 区别

- 响应式

Vue2 基于 `Object.defineProperty` 劫持对象属性。初始化时需要递归对象，有性能开销；无法完整监听对象属性新增、删除，也不能完美监听数组下标，所以需要 `$set` / `$delete`。

Vue3 基于 `Proxy`，可以拦截对象属性的读取和写入。深层对象只有真正访问时才会继续代理。基础类型无法被 `Proxy` 代理，所以 `ref` 通过 getter / setter 拦截读取和修改。

- 写法

Vue2 主要使用 Options API，如 `data`、`methods`。

Vue3 可以使用 Options API，也可以使用 Composition API，如 `ref`、`reactive`。

- TypeScript

Vue3 使用 TypeScript 编写，类型支持比 Vue2 更好。

- 根节点

Vue2 组件必须有单独根节点。

Vue3 组件允许多个根节点。

- diff

Vue2 是双端 diff，通过四个指针从两端向中间靠拢。头尾插入、删除比较高效，复杂乱序时移动次数不一定最优。

Vue3 引入快速 diff，先处理前后缀相同节点，再用最长递增子序列减少 DOM 移动。编译器还会生成 Patch Flags，让运行时跳过静态节点。

- build

Vue3 底层使用 ESM，更适合 Tree Shaking。

## v-if / v-show

- `v-if`：条件不满足时不渲染 DOM，切换时有创建和销毁成本。
- `v-show`：DOM 一直存在，通过 `display: none` 控制显示隐藏，不能用在 `template` 上。

## 万级数据渲染

项目中的数据是矢量数据，后端返回地块经纬度和地块信息。前端把数据交给 Web Worker，在子线程里用 turf.js 转成 GeoJSON，再通过 `postMessage` 返回主线程渲染。

数据量继续增大时，可以考虑：

- 后端预切矢量切片，前端按需加载。
- 前端使用 `geojson-vt` 动态切片。
- 使用 turf 做抽稀简化。
- 使用聚合图代替全量散点。

## 图片预加载

后台管理系统静态图片较多，进入页面后再请求图片会影响体验。

做法：

- 基于 Vite 插件处理。
- 在 `transformIndexHtml` 钩子中扫描图片路径。
- 生成 `link rel="prefetch"` 标签插入 `index.html`。
- 浏览器空闲时预加载图片，避免影响首屏加载。

## 组件懒挂载

页面内容多、计算量大时，可以让不可见组件先不挂载。

做法：

- 放一个占位元素。
- 使用 `IntersectionObserver` 监听占位元素是否进入视口。
- 进入视口后用 `v-if` 渲染真实组件。
- 渲染后取消监听。
